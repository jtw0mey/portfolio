Premier League xG Analytics Engine

My first automated ETL pipeline & interactive Streamlit dashboard

Overview

This is my first end-to-end data engineering project. As a football fan looking to expand beyond static data analysis into automated data workflows, I wanted to build a complete pipeline from scratch: collecting raw Expected Goals (xG) metrics from the web, cleaning and transforming the data, querying it with SQL, and building a live dashboard to display the results.

  • 🚀 Live Interactive Dashboard
  • 💻 GitHub Repository

How the Pipeline Works

  • Extract: Uses Python (`AsyncIO` and `aiohttp`) to harvest player and team performance data from Understat APIs into raw JSON files.
  • Transform: Uses Pandas to clean messy HTML character codes in player/team names and calculates per-90 metrics (xG/90, npxG/90, xGA/90) and overperformance (Goals − xG).
  • Load & Query: Saves processed data as CSV files. DuckDB executes fast in-memory SQL queries directly over these files inside the web app.
  • Automate: Scheduled via GitHub Actions to automatically re-run the pipeline every day at 04:00 UTC so the data stays updated hands-free.
  • Testing & Reliability: Includes basic unit tests written with `pytest` and error-handling checks so api/data issues don't crash the dashboard.

Tech Stack

  • Language: Python 3.11
  • Data Processing & SQL: Pandas, DuckDB
  • Data Collection: `understat`, `AsyncIO`, `aiohttp`
  • Dashboard & Visualization: Streamlit, Plotly
  • Testing & Automation: pytest, GitHub Actions
  • Hosting: Streamlit Community Cloud

AI-Assisted Development

Working this way allowed me to build a functional, end-to-end system while gaining practical understanding of asynchronous scripting, SQL engines, unit testing, and automated scheduling.

What I Learned

  • Connecting the Extract, Transform, and Load stages into a single automated pipeline
  • Cleaning raw web data and handling special characters with Pandas
  • Executing serverless SQL queries on file datasets using DuckDB
  • Setting up automated workflows and daily cron jobs with GitHub Actions
  • Writing unit tests with `pytest` to prevent broken data builds
